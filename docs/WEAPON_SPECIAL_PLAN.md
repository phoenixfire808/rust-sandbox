# Special weapon prototype: gravity gun

## Research

- Read Valve's public Source SDK 2013 [weapon_physcannon.cpp](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/server/hl2/weapon_physcannon.cpp) (read-only). It defines authored engine convars including `physcannon_maxmass` (250), `physcannon_tracelength` (250), `physcannon_minforce` (700), `physcannon_maxforce` (1500), `physcannon_pullforce` (4000), and `player_throwforce` (1000). Its carry path uses a motion/shadow controller, mass changes, velocity/damping restoration, and specialized pickup checks. Those details are evidence about this SDK source, not proof of exact installed Garry's Mod behavior.
- Read installed `scripts/weapons/weapon_physcannon.txt` through the existing read-only mounted inspector. Its `WeaponData` explicitly assigns viewmodel `models/weapons/c_physcannon.mdl` and playermodel `models/weapons/w_Physics.mdl`, with stock sound slots for launch, pickup, drop, and too-heavy feedback. This distinguishes the ordinary gravity-gun model from the super-upgrade `c_superphyscannon` physgun model.
- The prototype reuses the existing world trace, spawned-prop ownership, Rapier dynamic-body velocity, audio, and weapon equip/input lifecycle. CSV values are independent tuning choices and are not Source-unit conversions or physics equivalence.

## Implemented subset

`source_gravity.csv` is the only source for this subset's ranges, mass cutoffs, impulse, pull/hold spring, cooldown, and launch tuning. Left-click punts or launches. Right-click starts a range-limited pull, which attaches only when the prop reaches the actor-clear hold point; another right-click drops a held prop. Hold/punt require eligible dynamic spawned props under distinct configured limits. Eligibility uses Rapier's synchronized `ReadMassProperties` total mass, or explicit `ColliderMassProperties::Mass` / `MassProperties` while readback is not ready; absent/invalid mass is rejected rather than estimated. NPCs, vehicles, devices, posers, static props, and despawned entities are excluded. Weapon switch, blocked UI/focus/input, target occlusion, and invalid target clear the private gravity state without modifying the physgun's `PlayState.held`.

The implementation uses a bounded velocity spring instead of the native shadow controller, so inertia, orientation, collision handling, and native pickup semantics remain absent. Actor clearance uses configured hold distance plus a conservative radius from authored prop bounds; manual acceptance should check large/asymmetric props and corners. Read-only mounted metadata inspection confirmed the script-selected view model `models/weapons/c_physcannon.mdl` has `@idle`, `@draw`, `@fire`, and `@altfire`; `models/weapons/w_physics.mdl` has `@idle` and `@attack1`. The earlier `c_superphyscannon.mdl` inspection only confirmed that the physgun mesh also contains similar clips, not that it is the gravgun's correct model. Metadata confirms clip names, not successful decode/playback or native animation timing. Authored reach/hold limits are bounded meter-scale prototype choices. Original audio names are wired for `fire`, accepted `pull`, explicit `drop`, and rejected `denied`; pitch and cue timing remain unimplemented. No medkit work was attempted because health/resource semantics are outside this slice.
